================================================================================
MODELOS PRINCIPALES
================================================================================

1. RESTAURANTE (restaurantes/models.py)
   ├── usuario (OneToOne → User)
   ├── nombre, slug, tipo, descripcion, direccion, telefono, email
   ├── logo, portada (ImageField)
   ├── activo, verificado, mostrar_precios, acepta_pedidos, acepta_reservas
   ├── qr_uuid (UUIDField), qr_code (ImageField)
   ├── visitas_qr, total_pedidos
   ├── fecha_registro, ultima_actualizacion
   └── Métodos: save(slug+QR), get_qr_url(), incrementar_visitas(), total_platos()

2. CATEGORIA (menu/models.py)
   ├── restaurante (FK → Restaurante)
   ├── nombre, descripcion, orden, activa, icono
   └── unique_together: [restaurante, nombre]

3. PLATO (menu/models.py)
   ├── categoria (FK → Categoria)
   ├── nombre, descripcion, precio, imagen
   ├── disponible, destacado, es_vegetariano, es_picante, contiene_gluten
   ├── calorias, tiempo_preparacion (min)
   ├── veces_pedido (contador)
   └── imagen_miniatura (ImageSpecField → 300x300 WEBP)

4. PEDIDO (pedidos/models.py)
   ├── restaurante (FK → Restaurante)
   ├── codigo (auto, 8 chars únicos)
   ├── nombre_cliente, telefono_cliente, mesa, notas
   ├── estado [pendiente|confirmado|preparando|listo|entregado|cancelado]
   ├── metodo_pago [efectivo|transferencia|tarjeta]
   ├── total, pagado
   ├── fecha_creacion, fecha_confirmacion, fecha_listo, fecha_entregado
   └── Métodos: calcular_total(), progreso (%)

5. ITEM PEDIDO (pedidos/models.py)
   ├── pedido (FK → Pedido)
   ├── plato (FK → Plato)
   ├── cantidad, precio_unitario, subtotal, notas
   └── save(): calcula subtotal, actualiza total, incrementa contador

6. RESERVA (reservas/models.py)
   ├── restaurante (FK → Restaurante)
   ├── codigo (auto, R000001)
   ├── nombre_cliente, telefono, email, personas
   ├── fecha, hora, duracion, mesa, notas
   ├── estado [pendiente|confirmada|cancelada|completada|no_show]
   ├── confirmada_por (FK → User), confirmado_en
   ├── fecha_creacion, fecha_actualizacion
   └── Métodos: save(codigo), confirmar(usuario), cancelar(), completar()

7. NOTIFICACION (core/models.py)
   ├── usuario (FK → User)
   ├── tipo [reserva_nueva|reserva_confirmada|reserva_cancelada|pedido_nuevo|pedido_listo|sistema]
   ├── titulo, mensaje, data (JSON), leida, url
   ├── creada_en, leida_en
   └── crear_notificacion() (classmethod)

8. OTRAS (core/models.py):
   ├── Auditoria, ConfiguracionSistema, PlantillaEmail
   ├── Backup, MetodoPago, Transaccion, Factura

================================================================================
LÓGICA LOCAL vs ONLINE (DETECCIÓN DE IP)
================================================================================

Función is_private_ip() en clientes/views.py:
  - 10.0.0.0/8     → LOCAL
  - 172.16.0.0/12  → LOCAL
  - 192.168.0.0/16 → LOCAL
  - 127.0.0.1      → LOCAL

Si es_local=True:
  → Muestra controles de cantidad + botón "Agregar al carrito"
  → Carrito flotante (localStorage)
  → Permitido crear pedidos

Si es_local=False:
  → Solo muestra precios
  → Mensaje: "Conéctate al WiFi del restaurante para hacer pedidos"
  → API de pedidos retorna 403 Forbidden
